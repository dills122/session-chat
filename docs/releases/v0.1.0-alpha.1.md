# Session Chat `v0.1.0-alpha.1`

Release date: 2026-09-05

Status: source-only Phase 1 protocol-laboratory prerelease

## Purpose

This prerelease marks completion of the Session Chat 2.0 Phase 1 protocol
laboratory. It gives implementers and reviewers a stable source checkpoint for
the two-person capability-admission and MLS lifecycle, its retained hostile and
recovery evidence, and the separate scripted Iroh cross-computer experiment.

It is an alpha of the protocol laboratory. It is not a deployable chat product
or the security-focused product release defined in the roadmap.

## What is included

- Canonical, bounded capability invitations and HPKE-protected join requests.
- Exact KeyPackage ownership validation, explicit simulated approval, replay
  handling, invitation consumption, and a two-party MLS Add/Welcome flow.
- Encrypted bidirectional MLS application messages, a path update, member
  removal, and rejection after removal.
- SQLCipher laboratory transactions and application-process-kill recovery for
  invitation, authorization, MLS, KeyPackage, and Welcome-outbox state.
- Deterministic adverse transport traces for loss, delay, duplication,
  reordering, corruption, stale replay, acknowledgement loss, and queue
  saturation.
- A bounded independent-process conformance runner over local test channels.
- An explicitly selected `sessionctl-net` proof that carries the scripted
  lifecycle between two computers over an authenticated Iroh FastV1 link.

This release does not publish Rust crates.

## Try it locally

Install the repository-pinned Rust toolchain, clone this tag, and run:

```sh
cargo fetch --locked
cargo run -p sessionctl --locked --offline
```

The local two-process demonstration is:

```sh
cargo run -p sessionctl --bin sessionctl-pair --locked --offline -- host /tmp/session-chat-pair
cargo run -p sessionctl --bin sessionctl-pair --locked --offline -- join /tmp/session-chat-pair
```

Run those commands in separate terminals, starting the host first. The chosen
run directory must be a new absolute path.

## Try it across two computers

Both computers must use this exact tag and be able to reach Iroh's public N0
address-lookup and relay services.

On the host computer:

```sh
cargo run -p sessionctl --bin sessionctl-net --locked -- host /tmp/session-chat-network-host
```

After the host prints `invitation=ready`, transfer
`/tmp/session-chat-network-host/direct/invitation.v2` to the joining computer
through a separate authenticated, confidential channel. The printed endpoint
ID is public, while the invitation file is secret bearer admission authority.

On the joining computer, use a different new absolute state directory:

```sh
cargo run -p sessionctl --bin sessionctl-net --locked -- join HOST_ENDPOINT_ID /tmp/session-chat-invitation.v2 /tmp/session-chat-network-join
```

The proof succeeds when both processes print `status=complete`. This exercises
the protected join, Welcome, two fixed MLS application messages, path update,
removal, and post-removal rejection. It does not provide a prompt for arbitrary
chat messages. See the [`sessionctl` guide](../../apps/sessionctl/README.md) for
the complete operating and cleanup notes.

## Alpha limits

- There is no interactive chat interface, desktop package, installer, hosted
  rendezvous service, or human approval screen.
- The Iroh path is an online, one-connection feasibility experiment with
  ephemeral endpoint keys. It is not the planned reusable Fast transport.
- The invitation must be transferred out of band. Losing it exposes admission
  authority to its holder.
- Direct peers and Iroh/N0 infrastructure may observe network addresses,
  endpoint identifiers, timing, sizes, and lookup metadata. This is not a
  Private-mode or anonymity demonstration.
- Product key custody, platform vaults, rollback resistance, physical power-loss
  evidence, backups, secure deletion, reconnect, offline delivery, and signed
  updates remain later work.
- No third-party security review or production deployment claim is made.

GitHub supplies automatic source archives for the tag. This prerelease does not
attach signed binaries, an installer, an SBOM, an attestation, or an update
channel. Release and update provenance remain a later product gate.
