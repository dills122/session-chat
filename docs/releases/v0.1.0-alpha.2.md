# Session Chat `v0.1.0-alpha.2`

Release date: 2026-09-08

Status: source-only, security-stabilized protocol-laboratory prerelease

## Purpose

This prerelease is the recommended checkpoint for the planned two-computer
test. It retains the Phase 1 two-person capability-admission and MLS lifecycle
from `v0.1.0-alpha.1`, then adds the completed security-audit fixes, connected
FastV1 transport evidence, and stabilized CI/release gates.

It remains an alpha of the protocol laboratory. It is not a deployable chat
product or the security-focused product release defined in the roadmap.

## What changed since `v0.1.0-alpha.1`

- Connected the bounded Iroh FastV1 adapter to common transport-conformance
  evidence while retaining explicit `auto` and `relay-only` path disclosure.
- Hardened untrusted ingress with bounded parsing and work, deadlines, poison
  handling, authentication-before-state-change ordering, and adverse tests.
- Tightened invitation, restart-key, evidence, and diagnostic secret boundaries.
- Bound local state and evidence cleanup to retained filesystem handles and
  rejected replacement, symlink, reparse-point, and rollback ambiguity.
- Added fail-closed Windows handoff creation and reading with an exact protected
  Owner Rights/System-only DACL.
- Hardened dependency, action, Pages, build-provenance, L2 artifact, and AI
  Central verification gates.
- Closed final security-audit blockers #320, #321, and #328 with Linux, macOS,
  Windows, CodeQL, dependency, coverage, and checked L2 evidence.

This release does not publish Rust crates or binaries.

## Try it locally

Install the repository-pinned Rust toolchain, clone this tag, and run:

```sh
cargo fetch --locked
cargo run -p sessionctl --locked --offline
```

The local two-process demonstration is:

```sh
cargo run -p sessionctl --bin sessionctl-pair --locked --offline -- host /tmp/session-chat-pair
cargo run -p sessionctl --bin sessionctl-pair --locked --offline -- join /tmp/session-chat-pair
```

Run those commands in separate terminals, starting the host first. The chosen
run directory must be a new absolute path.

## Try it across two computers

Both computers must use this exact tag and be able to reach Iroh's public N0
address-lookup and relay services.

On the host computer:

```sh
cargo run -p sessionctl --bin sessionctl-net --locked -- host /tmp/session-chat-network-host
```

After the host prints `invitation=ready`, transfer
`/tmp/session-chat-network-host/direct/invitation.v2` to the joining computer
through a separate authenticated, confidential channel. The printed endpoint
ID is public, while the invitation file is secret bearer admission authority.

Recommended handoff is an existing end-to-end encrypted messenger conversation
with the intended recipient whose contact identity you already trust. Send
`invitation.v2` as a file attachment; the public endpoint ID may be sent in the
same conversation. Do not paste or post the invitation, upload it to a public
link, or send it through ordinary email. Complete the handoff while the host's
five-minute connection window is open. After both clients report
`status=complete`, remove the downloaded invitation and the sent attachment or
message where the messenger permits it. Messenger backups or the recipient
device may still retain copies, so deletion is cleanup rather than a
secure-erasure guarantee. The messenger transports the bearer capability only;
it is not part of Session Chat's admission, MLS, or Iroh security boundary.

On the joining computer, use a different new absolute state directory:

```sh
cargo run -p sessionctl --bin sessionctl-net --locked -- join HOST_ENDPOINT_ID /tmp/session-chat-invitation.v2 /tmp/session-chat-network-join
```

The proof succeeds when both processes print `status=complete`. It exercises
protected join, Welcome, two fixed MLS application messages, path update,
removal, and post-removal rejection. It does not provide a prompt for arbitrary
chat messages.

On Windows, the joiner additionally requires the transferred invitation file
to have the exact protected Owner Rights/System-only DACL. Files carrying an
inherited or permissive download ACL fail closed. This prerelease does not yet
provide a portable import command that repairs a downloaded file's ACL; use the
Linux/macOS path for the immediate cross-computer trial unless the Windows file
has been placed with that exact policy.

See the [`sessionctl` guide](../../apps/sessionctl/README.md) for complete
operating and cleanup notes.

## Alpha limits

- There is no interactive chat interface, desktop package, installer, hosted
  rendezvous service, or human approval screen.
- The Iroh path is an online, bounded one-connection experiment with ephemeral
  endpoint keys. It is not an offline mailbox or production Private transport.
- The invitation must be transferred out of band. Losing it exposes admission
  authority to its holder.
- Direct peers and Iroh/N0 infrastructure may observe network addresses,
  endpoint identifiers, timing, sizes, and lookup metadata. This is not an
  anonymity demonstration.
- Product key custody, platform vaults, rollback resistance, physical power-loss
  evidence, backups, secure deletion, reconnect, offline delivery, and signed
  updates remain later work.
- No third-party security review or production deployment claim is made.

GitHub supplies automatic source archives for the tag. Attached testing-kit
archives, checksums, detached signature, public signing key, and machine-readable
evidence manifest cover this source-only checkpoint. This prerelease does not
attach binaries, an installer, an SBOM, or an update channel.
